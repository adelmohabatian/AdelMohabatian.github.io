# WebSocial Online Studio — پایلوت مدیریت آنلاین پژوهش فرش تبریز

این بسته **پنل لاگین اختصاصی داخل وب‌سایت نیست**؛ پیکربندی و اتصال امن پنل آنلاین Pages CMS به GitHub است. ورود مدیر از راه GitHub انجام می‌شود و همکار را می‌توان با دعوت ایمیلی در Pages CMS افزود.

## فایل‌ها

- `.pages.yml` فرم ویرایش آنلاین عکس‌ها، توضیح‌ها و یادداشت‌های مرتبط با فرش تبریز.
- `content/pilot/carpet.json` داده آزمایشی بدون ادعای میدانی.
- `content/pilot/media/` محل عکس‌های **مجاز به انتشار عمومی** که از پنل آپلود می‌شوند.
- `tools/websocial_online_pilot_builder.py` موتور مطمئن تولید ZIP و به‌روزرسانی گراف/گالری.
- `.github/workflows/websocial-editorial-preview.yml` ساخت خودکار نسخه پیش‌نمایش **بدون انتشار عمومی**.

## نصب روی GitHub (ویندوز ۱۰)

1. از مخزن GitHub و فایل `releases/site.zip` یک پشتیبان تهیه کن.
2. در GitHub Desktop شاخه آزمایشی `content-studio-dev` را انتخاب کن. فایل‌های این ZIP را از ریشه مخزن GitHub استخراج کن، **نه** در پوشه `site-source` و نه در `releases/site`.
3. وجود فایل `releases/site.zip` را بررسی کن. فایل جدید نباید ZIP قبلی سایت را جایگزین کند.
4. `git status` را بررسی کن؛ تغییرات باید شامل `.pages.yml` و `content/pilot/` و ابزار/Workflow جدید باشد؛ فایل‌های عکس موجود دست‌نخورده بمانند.
5. این تغییرات را فقط روی شاخه `content-studio-dev` Commit و Push کن؛ **به main منتقل نکن**.
6. به https://app.pagescms.org برو، با حساب GitHub وارد شو و GitHub App را فقط برای مخزن سایت نصب کن. مخزن و شاخه `content-studio-dev` را انتخاب کن.
7. در پنل، فایل `Tabriz carpet | pilot` را باز کن. یکی از توضیح‌های عکس را تغییر بده یا یادداشت آزمایشی جدید بساز؛ وضعیت را `draft` یا `review` نگه دار.
8. در GitHub > Actions اجرای `WebSocial editorial pilot preview` را بررسی و artifact با نام `websocial-editorial-review` را دانلود کن.
9. فایل `pilot-site.zip` داخل artifact را صرفاً برای پیش‌نمایش در پوشه‌ای جدا استخراج کن و با Python یک سرور محلی از آن پوشه اجرا کن. در `/photography/carpet/`, `/research/carpet/` و `/explore/?focus=carpet` تغییر را ببین.

## اجرای آزمایش محلی بدون CMS

از ریشه مخزن:

```cmd
python -m pip install Pillow
python tools\websocial_online_pilot_builder.py --base-zip releases\site.zip --data content\pilot\carpet.json --media-dir content\pilot\media --output preview\pilot-site.zip --include-drafts
```

سپس `preview\pilot-site.zip` را در پوشه جداگانه‌ای استخراج کن و از آنجا پیش‌نمایش بگیر. این دستور **هرگز سایت عمومی را منتشر نمی‌کند**.

## دعوت همکار

در بخش Collaborators پنل Pages CMS، ایمیل همکار را دعوت کن. پس از ورود، هر دو می‌توانید فرم‌ها را ویرایش کنید. توجه: مجوز همکار به **مخزن** وابسته است، نه یک سیستم تضمین‌شده تأیید مرحله‌ای. برای این آزمایش هیچ داده محرمانه وارد نشود و Branch/Ruleset حفاظت از `main` تنظیم گردد. در اولین آزمون، حتی اگر همکار برچسب `published` انتخاب کند، workflow ما روی شاخه آزمایشی **هیچ انتشار عمومی انجام نمی‌دهد**.

## مرز امنیتی / حریم خصوصی

- **ممنوع:** فایل مصاحبه خام، فهرست اسامی بدون رضایت، نشانی‌ها و شماره‌ها، عکس بدون رضایت انتشار، فایل محرمانه قرارداد یا اسناد حقوقی.
- **مجاز:** توضیح‌ها و عکس‌هایی که از پیش برای انتشار در وب‌سایت عمومی تأیید شده‌اند.
- مخزن عمومی GitHub برچسب `draft` را به معنای «محرمانه» نمی‌شناسد؛ داده روی شاخه توسعه نیز در Git قابل مشاهده خواهد بود.
- برای آرشیو خام و همکاری حساس، در مرحله بعد مخزن خصوصی/ذخیره‌سازی امن با نقش‌های کنترل‌شده لازم است.
- برای انتشار نهایی به GitHub Pages از نسخه تأییدشده و Workflow جداگانه استفاده می‌کنیم؛ در این بسته عمداً انتشار خودکار فعال نشده است.

## بعد از موفقیت آزمایش

پس از تأیید مدیر می‌توانیم انتشار مرحله‌ای را به GitHub Actions اصلی سایت متصل کنیم و بعدها پنل اختصاصی دارای احراز هویت، ثبت رویداد و مجوزهای دقیق بسازیم. این مرحله فقط اثبات امکان و آماده‌سازی داده برای آن انتقال است.
